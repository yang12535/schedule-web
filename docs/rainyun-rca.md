# 雨云 RCA 部署指南（准备中）

班级课表服务是一个无需数据库的轻量级 Web 应用，适合班级、社团和小团队发布课表、公告，并通过密码进行在线编辑。

雨云平台侧应用目前尚未完成。本文是上线前配置参考，不代表商店应用已经可用。

## 一键部署

正式模板 ID、商店地址和推广地址需等平台配置完成并审核通过后再确认。若内部测试使用预留 ID，请不要在平台完成前对外发布。

平台完成后，部署完成的用户可在雨云项目中打开“Web 管理页面”服务提供的公网地址访问应用。

## 最低配置

| 项目 | 要求 |
| --- | --- |
| CPU | 0.5 核 |
| 内存 | 256 MB |
| 内部端口 | 3000/TCP |
| 持久化目录 | `/data` |
| 健康检查 | `GET /healthz`，预期 HTTP 200 |

`/data` 是唯一必须持久化的目录，其中包含：

- `/data/schedule.json`：课表、设置和公告。
- `/data/logs/`：运行日志。

`/healthz` 会验证 `/data` 可写和原子重命名能力，并返回安全响应头。该接口用于平台探活，不计入用户访问量。

## 部署选项

| 选项 | 说明 | 建议 |
| --- | --- | --- |
| 班级名称 | 页面显示的课表名称 | 必填，1-50 个字符 |
| 学期描述 | 当前学期或班级说明 | 可选，最多 100 个字符 |
| 学期开始日期 | 用于计算当前周次 | `YYYY-MM-DD` |
| 编辑密码 | 编辑课程、设置和公告时使用 | 必填，启用平台随机生成 |

正式雨云模板应为每次部署生成独立编辑密码。部署后请立即保存到密码管理器，不要在公开文档或群聊中发送密码。

服务端对 `EDIT_PASSWORD` 的处理规则如下：

- 未设置：启动时随机生成 6 位密码。
- 设置为具体值：使用该固定密码。
- 显式设置为空字符串：关闭密码保护。

公网部署禁止使用空密码。正式雨云模板不应传入空密码。

## 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `NODE_ENV` | `production` | 运行环境 |
| `PORT` | `3000` | 容器内部监听端口 |
| `DATA_FILE` | `/data/schedule.json` | 课表数据文件 |
| `LOG_DIR` | `/data/logs` | 日志目录 |
| `TZ` | `Asia/Shanghai` | 容器时区 |
| `CLASS_NAME` | `我的课表` | 班级名称 |
| `CLASS_DESC` | 空 | 学期描述 |
| `SEMESTER_START` | 当年 `03-01` | 学期开始日期 |
| `EDIT_PASSWORD` | 自动生成 | 编辑密码 |

## 日志与访问统计

应用日志写入 `/data/logs/schedule-YYYY-MM-DD.log`。动态请求日志格式为：

```text
[HH:mm:ss] GET /api/schedule - IP: 127.0.0.1
```

统计历史访问量时，建议按天统计 `GET /api/schedule`，因为页面首屏会请求该接口；`/healthz` 是平台健康检查，不应作为用户访问量。管理日志接口需要使用 `x-password` header 传入编辑密码，避免密码进入 URL 和日志。

## 备份与恢复

备份时只需备份整个 `/data` 目录。恢复时停止应用，将备份内容覆盖回 `/data`，再启动应用。

至少应保留 `/data/schedule.json`。不要只备份容器本身，因为重建容器不会保留未挂载的数据。

## 镜像与版本

计划上架版本建议固定使用：

```text
ghcr.io/yang12535/schedule-web:1.1.2
```

正式应用模板中不要使用 `latest`，避免用户重建实例时意外升级到未经验证的版本。

镜像启动时会在挂载完成后修正 `/data` 的所有权，再以非 root 用户运行服务。健康检查会实际验证 `/data` 的写入和原子重命名能力；存储不可写时返回 HTTP 503，而不会提供一个无法保存的页面。
